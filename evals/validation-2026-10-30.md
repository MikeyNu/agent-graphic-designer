### Repair-studio inspection conditions

The prototype used local data and no external assets. The main composition did not use a hero pill or the stock copy/graphic split. Its functional form and supporting workshop information retained readable left alignment. The review explicitly stated that nothing had been sent, and the narrow review preserved readable text and reachable copy/download controls.

Responsive frames were measured rather than inferred from filenames: outer widths 335, 390, and 783 CSS px produced content `clientWidth` values 320, 375, and 768, respectively, with equal `scrollWidth` values. The 15 px difference was the browser scrollbar. These are desktop-browser frame checks, not physical-device tests. The generous mobile introduction is a density tradeoff, not evidence of optimal time to task; the guide now explicitly calls for inspecting the first useful choice and removing redundant introductory content on task-oriented entries.

### Dispatch-console inspection conditions

The interface used the supplied fictional jobs and technicians, with local assignment simulation and explicit limits on persistence and contact. Its main structure was an operational queue with an inspector, not a marketing hero or decorative KPI dashboard. The narrow layout provided a focused detail view and return action.

The execution agent reported correcting return focus after a job left the unassigned queue. Parent visual review then identified a one-pixel horizontal overflow and a truncated native select value in the narrow queue. Enlarged-text inspection also exposed navigation and table crowding. The agent revised containment, filter rows, navigation spacing, and text-responsive layout. The final narrow screenshot showed the complete selected region and urgency values, with `clientWidth` and `scrollWidth` both 305 CSS px inside the 320 px outer frame. The final enlarged-text screenshots showed readable navigation, job content, and reachable assignment controls.

The enlarged-text exercise doubled computed font sizes in a desktop-browser frame; it was not a physical device test or a full browser-zoom conformance audit. These checks support the inspected states only. The general interaction guide now warns that zero-overflow measurements cannot establish visual success: selected values, clipped text, overlaps, and internal scrolling require inspection too.
